# Starter Kit

**AgroKit** — Python-фреймворк, который организаторы предоставляют участникам,
чтобы те писали алгоритм, а не драйверы. Он скрывает моторы, кинематику,
сетевые протоколы и различия между симулятором и железом.

!!! note "Статус v0.1"

    AgroKit и Docker-образ доступны в репозитории. Базовые примеры работают;
    политика локомоции Go2 и обученный `agro_yolo` — в разработке.
    См. [Быстрый старт](quickstart.md).

---

## Что входит в набор

- **Контейнер с окружением** — симулятор, ROS 2 Humble, Unitree SDK, все
  зависимости. Собран под x86 и ARM.
- **Библиотека `agrokit`** — высокоуровневый API для обоих треков.
- **Готовые сцены** — виртуальный «сад» для Go2 и стол сортировки для G1
  (лабораторные аналоги агро-сценариев).
- **Предобученные модели** — базовый агро-детектор и контроллер локомоции.
- **Рабочие примеры** — минимальные решения для обоих треков, которые
  запускаются из коробки и служат отправной точкой.
- **Судейский скрипт** — тот же, что применяется при оценке, чтобы вы могли
  проверить себя до сдачи.

## API трека Go2

```python title="go2_scout.py"
from agrokit.go2 import Go2

go2 = Go2(sim=True)

for row in go2.field.rows:
    go2.nav.follow_row(row, speed=0.4)

    for det in go2.vision.detect(model="agro_yolo"):
        if det.label in ("powdery_mildew", "leaf_rust"):
            go2.report.add_finding(det.label, go2.nav.pose, det.score)

go2.report.export("field_report.json")
```

| Модуль | Основные методы |
|---|---|
| `go2.nav` | `goto(x, y, yaw)`, `follow_row(row, speed)`, `stop()`, свойство `pose` |
| `go2.vision` | `frame()`, `detect(model)`, `to_map(detection)` |
| `go2.map` | `build()`, `load(path)`, `rows`, `obstacles` |
| `go2.report` | `add_finding(label, pose, score)`, `export(path)` |

Ходьба робота вам не принадлежит и не оценивается: `nav` планирует маршрут через
Nav2, а встроенный контроллер локомоции превращает команду скорости в движение
лап. На реальном роботе работает тот же контроллер, поэтому поведение совпадает.

## API трека G1

```python title="g1_sorting.py"
from agrokit.g1 import G1

g1 = G1(sim=True)

for fruit in g1.vision.detect(model="agro_yolo"):
    g1.arm.move_to_point(x=fruit.x, y=fruit.y, z=fruit.z)
    g1.hand.set_gesture("PINCH", speed=0.3)
    g1.arm.move_to_point(*g1.trays[fruit.grade])
    g1.hand.set_gesture("OPEN")
```

| Модуль | Основные методы |
|---|---|
| `g1.arm` | `move_to_point(x, y, z)`, `move_home()`, `reachable(point)` |
| `g1.hand` | `set_gesture(name, side, speed)`, `set_joints(values)`, `state()` |
| `g1.vision` | `frame()`, `detect(model)`, `pose_of(detection)` |
| `g1.trays` | Координаты лотков по категориям качества |

Управление кистью сведено к именованным пресетам — `PINCH`, `POWER_GRIP`,
`OPEN`. Разбираться с двенадцатью моторами и протоколом RS485 не нужно;
подробности того, как это устроено внутри, описаны
[в разделе трека G1](tracks/g1.md#управление-кистью).

## Переход от симуляции к железу

Единственное, что меняется при переходе в лабораторию NEWUU, — параметры
подключения.
Логика решения остаётся прежней.

=== "Симуляция"

    ```python
    robot = Go2(sim=True)
    # domain_id = 1, интерфейс "lo"
    ```

=== "Реальный робот"

    ```python
    robot = Go2(sim=False, iface="enp3s0")
    # domain_id = 0, физический интерфейс
    ```

!!! warning

    Флаг `sim=False` разрешается использовать только в лаборатории Организатора
    под наблюдением судьи. См. [правила безопасности](stack.md#правила-безопасности).

## Структура решения

Команда сдаёт репозиторий следующего вида:

```
solution/
├── main.py            # точка входа, вызывается судейским скриптом
├── perception/        # ваши модели и обработка изображений
├── control/           # логика навигации или манипуляции
├── models/            # веса, если дообучали детектор
├── requirements.txt   # дополнительные зависимости
└── README.md          # описание подхода и инструкция запуска
```

Судейский скрипт запускает `main.py` в стандартном контейнере на фиксированной
сцене. Если решению нужны дополнительные пакеты, они должны быть перечислены в
`requirements.txt` и устанавливаться без доступа в интернет во время прогона.

## Ограничения, о которых стоит знать заранее

**Схват позиционный.** Кисть G1 отрабатывает заданные углы пальцев; обратной
связи по усилию в базовом API нет. Для мягких плодов используйте пониженную
скорость сжатия и подбирайте целевую позицию экспериментально.

**Детектор из коробки — только отправная точка.** Базовая модель обучена на
ограниченном наборе и на реальных снимках теряет точность. Дообучение под
конкретные условия освещения — ожидаемая часть работы команды.

**Прогон детерминирован.** Судейский скрипт фиксирует зерно случайности, чтобы
результат был воспроизводим. Решения, полагающиеся на удачу конкретного
запуска, устойчивого результата не покажут.
