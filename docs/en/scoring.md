# Scoring

!!! note "Draft scale"

    The weights below reflect the current draft of the [rules](rules.md). Final
    values will be fixed in the official edition before the qualifier starts.

---

## Criteria

| Weight | Criterion | What is measured |
|---:|---|---|
| 35% | **Task completion** | Share of route completed, number of correctly found or sorted objects |
| 25% | **Perception quality** | Detection accuracy and recall, robustness to lighting and viewpoint, no false positives |
| 15% | **Autonomy** | Number of operator interventions per run |
| 15% | **Reliability and time** | Result repeatability across runs, scenario completion time |
| 10% | **Engineering culture** | Code readability, reproducible build, documentation and report quality |

---

## How this works in practice

**Autonomy matters more than speed.** A fully autonomous run scores higher than a
fast run with manual hints. A robot that completed the task slowly on its own is
more valuable than one that completed it quickly with human help.

**False positives are penalized as much as misses.** A detector that marks every
second plant as diseased is useless to an agronomist: checking everything manually
is cheaper than trusting such a report. Accuracy and recall are evaluated together.

**Reliability is tested with repeats.** The scenario is run several times, and a
stable result counts, not the best attempt. A solution that works every other run
will score lower than a consistent one.

**Engineering culture is not about style.** Evaluators check whether your project
builds on a clean machine using your own instructions, whether your report makes
clear what you did, and whether another team can reproduce the result.

---

## Using third-party code

Open libraries and pretrained models with compatible licenses may and should be
used — list them in your report.

Your engineering work is evaluated: fine-tuning on the agro dataset, component
integration, failure handling, and reliability on real hardware. Writing a detector
from scratch does not add points by itself.

!!! danger "What is not allowed"

    Direct borrowing of another team's solution and tuning to a specific judging
    scene while bypassing general logic (for example, hard-coded object coordinates
    instead of detection). Such solutions are removed from scoring — see
    [fair play rules](rules.md#9-fair-play-rules).

---

## Team report

Each stage solution includes a brief report: chosen approach, what worked, what
did not, and which external components were used. Length is a few pages; substance
matters more than length.

For the Go2 track, the **farmer report** generated by the robot itself is scored
separately: it must be both machine-readable (JSON for the judging script) and
human-readable.
