# Track 2 — Unitree G1

## “Smart agro sorter”

**Focus:** manipulation, anthropomorphic grasp, computer vision, teleoperation, and
learning from demonstration.

The humanoid works at a sorting station: it sees fruit on the table, assesses
quality, grasps with a suitable grip, and sorts into trays. Balance and torso control
are not part of the competition — on the G1 stand the robot is secured on a safety
harness, and your task starts at the arm and hand level.

---

## Stage 1 — Simulation

**Environment:** G1 model in front of a table with **artificial** fruit and vegetables
of different colors and shapes.

**Task:** recognize objects, plan arm trajectory through inverse kinematics, place
them into trays.

What matters at this stage:

- correctly determine object category and position;
- plan trajectory without collisions with the table, trays, or the robot itself;
- choose grasp suited to object shape;
- do not drop the object on the way to the tray.

---

## Stage 2 — Real G1

**Location:** stand in the NEWUU laboratory with safety harness (gantry).

**Task:** autonomous grasp of **artificial** test objects from the table using
ready grasp presets and sorting by quality category and color.

On real hardware, contact appears: objects slip in the fingers, smooth plastic gives
less friction than in the simulator, and positioning accuracy is limited by camera-to-arm
calibration. Allow time for calibration — it determines success more than the planning
algorithm itself.

---

## Stage 3 — Final

**Task:** work through Teleoperation Kit — gloves for hand control.

Two strategies are possible, and both count:

- **Learning from demonstration.** A human demonstrates grasps through gloves; the
  team records a dataset and trains a fast-grasp policy on it.
- **Teleoperation as backup.** The robot runs autonomously; the operator intervenes
  selectively where autonomy falls short.

---

## Hand control

G1 hands have six degrees of freedom per arm. Controlling them directly means
assembling a vector of twelve values in the correct finger order and watching ranges.
The Starter Kit hides this behind named presets.

```python title="g1_sorting.py"
from agrokit.g1 import G1

g1 = G1(sim=True)

for fruit in g1.vision.detect(model="agro_yolo"):
    g1.arm.move_to_point(x=fruit.x, y=fruit.y, z=fruit.z)
    g1.hand.set_gesture("PINCH", speed=0.3)      # (1)!
    g1.arm.move_to_point(*g1.trays[fruit.grade])
    g1.hand.set_gesture("OPEN")
```

1.  Reduced closing speed is a basic technique for fragile and smooth artificial
    fruit: the hand reaches the target position smoothly, reducing peak force on the
    object.

### Grasp presets

| Preset | Use |
|---|---|
| `PINCH` | Pinch grasp: berries, stems, small fruit |
| `POWER_GRIP` | Power wrap: bottles, tools, large fruit |
| `OPEN` | Open palm: release object, home position |

!!! warning "Grasp is positional, not force-based"

    The hand moves to commanded finger angles; there is no force feedback in the base
    API. You cannot “squeeze to the right force” — tune target position and closing
    speed for each object and verify on test runs.

??? info "How it works under the hood"

    Hands are controlled via DDS topic `rt/inspire/cmd` with message `MotorCmds_`,
    containing an array of **12 values** — right hand first, then left, six degrees
    of freedom each:

    | Index | 0–5 (right) | 6–11 (left) |
    |---|---|---|
    | Order | pinky, ring, middle, index, thumb bend, thumb rotation | same |

    Each value ranges from `0` (closed) to `1000` (open). Hand state arrives on topic
    `rt/inspire/state`. Only position `q` is meaningful; force fields in this interface
    are reserved. A bridge service converting DDS to RS485 must run on the robot.

    The `set_gesture()` preset is simply a named set of target values mapped to the
    correct array indices.

## Available modules

| Module | Purpose |
|---|---|
| `g1.arm` | Move arm to point, inverse kinematics, reachability check |
| `g1.hand` | Grasp presets, arbitrary finger positions, hand state readout |
| `g1.vision` | Camera frames, object detection, object pose on table |
| `g1.trays` | Tray coordinates by quality category |
